Раздел каталога внешнего API позволяет управлять материалами/декорами, фасадами, ручками и комплектующими. Общие правила (базовый URL, `sync_key`, применение `apply_data`) — в статье [«Публичное API: обзор»](/Tilda-PlanPlace/api-publichnoe-obzor/).

## Шаблон методов и поддержка по разделам

Методы каталога построены по шаблону **действие + раздел**: `ОсновнойURL/api/<действие>/<раздел>`. Например, `api/get_items/materials`.

> **Важно: не все действия доступны для всех разделов.** Это не недоработка — для части разделов через API реализованы только чтение и добавление. Ниже — точная матрица того, что реально поддерживается.

| Раздел | `get_items` (чтение) | `add_items` (добавить) | `update_items` (обновить) | `remove_items` (удалить) |
|---|:---:|:---:|:---:|:---:|
| `materials` — материалы/декоры | ✅ | ✅ | ✅ | ✅ |
| `facades` — фасады | ✅ | ✅ | ✅ | ✅ |
| `handles` — ручки | ✅ | ✅ | ✅ | ✅ |
| `accessories` — комплектующие | ✅ | ✅ | ✅ | ✅ |
| `tech` — техника | ✅ | ✅ | — | — |
| `interior` — интерьер | ✅ | ✅ | — | — |
| `comms` — коммуникации | ✅ | ✅ | — | — |
| `orders` — заказы | ✅ (только чтение) | — | — | — |

То есть **полный набор (включая обновление и удаление) есть только у `materials`, `facades`, `handles`, `accessories`.** Для остальных разделов через API доступны только чтение (`get_items`) и добавление (`add_items`) — обновлять и удалять их нужно в кабинете.

**Категории** — `get_categories` / `add_categories` / `update_categories` / `remove_categories` для разделов, у которых есть категории (materials, facades, handles и др.). Категория описывается полями `id`, `name`, `parent` (`"0"` — верхний уровень).

> **Устаревший метод (наследие 1.0).** В системе остался legacy-метод `GET api/get_items/materials_v1` — он возвращает материалы в **старом формате версии 1.0**. Для 2.0 используйте `get_items/materials`; `materials_v1` нужен только для совместимости со старыми интеграциями и в новых разработках не применяется.

Общие правила:

- **GET** (чтение): `sync_key` передаётся параметром строки запроса;
- **POST** (запись): тело содержит `data` (JSON) и `sync_key`;
- ответ — JSON (для записи обычно `"success"` / `"error"`, для чтения — массив объектов);
- после изменений вызывайте `GET api/apply_data?sync_key=...`.

## Материалы и декоры

### Получить материалы

```
GET  ОсновнойURL/api/get_items/materials?sync_key=ВАШ_КЛЮЧ
```

Ответ — массив материалов. Поля объекта:

| Поле | Тип | Описание |
|---|---|---|
| `id` | number | ID материала |
| `name` | string | название |
| `code` | string | артикул |
| `order` | number | порядок отображения |
| `category` | number | id категории |
| `params` | object | параметры отображения |
| `add_params` | object | дополнительные параметры |

Объект **`params`**:

| Поле | Тип | Описание |
|---|---|---|
| `color` | string | HEX-код цвета |
| `map` | string | URL изображения текстуры |
| `roughness` | number | шероховатость, 0–1 |
| `metalness` | number | металличность, 0–1 |
| `transparent` | boolean | прозрачность (только для PNG с прозрачными участками) |

Объект **`add_params`**:

| Поле | Тип | Описание |
|---|---|---|
| `real_width` | number | реальная ширина текстуры в мм |
| `real_height` | number | реальная высота текстуры в мм |
| `stretch_width` | boolean | растягивать текстуру по ширине |
| `stretch_height` | boolean | растягивать текстуру по высоте |
| `wrapping` | string | тип наложения: `repeat` (повтор) или `mirror` (зеркальные края) |

**Пример элемента ответа:**

```json
{
  "id": 104,
  "name": "2516-LArpa",
  "code": "2516",
  "category": 16,
  "params": {
    "color": "#ffffff",
    "map": "https://test.com/images/image.jpg",
    "roughness": 0.8,
    "metalness": 0,
    "transparent": false
  },
  "add_params": {
    "real_width": 256,
    "real_height": 256,
    "stretch_width": false,
    "stretch_height": false,
    "wrapping": "mirror"
  }
}
```

### Добавить, обновить, удалить материалы

```
POST  ОсновнойURL/api/add_items/materials        (data + sync_key)
POST  ОсновнойURL/api/update_items/materials     (data + sync_key)
POST  ОсновнойURL/api/remove_items/materials     (data + sync_key)
```

Для добавления/обновления `data` — массив объектов материалов того же формата, что в ответе `get_items`. Для удаления — список идентификаторов.

### Обновить только артикулы материалов

Отдельный метод — массово обновить артикулы (полезно при смене кодов из 1С без правки остальных полей):

```
POST  ОсновнойURL/api/update_items_code/materials   (data + sync_key)
```

### Категории материалов

```
GET   ОсновнойURL/api/get_categories/materials?sync_key=ВАШ_КЛЮЧ
POST  ОсновнойURL/api/add_categories/materials      (data + sync_key)
POST  ОсновнойURL/api/update_categories/materials   (data + sync_key)
POST  ОсновнойURL/api/remove_categories/materials   (data + sync_key)
```

Категория описывается полями `id`, `name`, `parent` (`"0"` — верхний уровень).

## Модули пользовательского каталога

Для модулей из пользовательского каталога используются отдельные методы. Параметр `key` — ключ каталога, например `_kmodule`. Его нужно получить из настроек конкретного каталога; подставлять название категории вместо ключа нельзя. Сохраняйте начальные подчёркивания в ключе.

### Получить список модулей

```http
GET ОсновнойURL/api/get_catalog_module_items?sync_key=ВАШ_КЛЮЧ&key=_kmodule
```

Необязательные параметры:

- `limit` или `per_page` — сколько элементов вернуть;
- `offset` или `start` — с какого элемента начать выборку.

Ответ содержит массив `items`, общее количество `count`, ключ каталога и применённые параметры пагинации. Элементы идут по полю `order`, затем по `id`.

### Получить один модуль

```http
GET ОсновнойURL/api/get_catalog_module_item?sync_key=ВАШ_КЛЮЧ&key=_kmodule&id=22
```

В успешном ответе объект модуля находится в поле `item`. Если каталог или запись не найдены, API вернёт ответ с `result: "error"` и описанием причины.

### Добавить или изменить модуль

```http
POST ОсновнойURL/api/add_catalog_module_item
POST ОсновнойURL/api/update_catalog_module_item
```

Передавайте `sync_key` и `key` в теле запроса. Для изменения также обязателен `id`. Поддерживаются поля:

| Поле | Назначение |
|---|---|
| `name` | название модуля |
| `order` | порядок в каталоге |
| `active` | `1` — показывать модуль, `0` — отключить |
| `data` | полный объект параметров модуля в JSON |

`data` можно передать как JSON-строку или объект. При изменении указывайте только те верхнеуровневые поля, которые действительно нужно заменить. Если передаёте новый объект `data`, сначала получите текущую запись и сохраните в нём все необходимые параметры конструкции.

- `name`, `active`, `order`, `category` — название, доступность, порядок и категория; часть этих значений также хранится в отдельных полях записи.
- `code` — шаблон артикула: обозначения в фигурных скобках подставляют значения при формировании артикула.
- `element_type` — ключ типа элемента каталога; здесь `_kmodule`, в отличие от `params.type`, который обозначает тип корневого узла конструкции.
- `params.size` — текущие размеры модуля в миллиметрах по осям X, Y и Z.
- `params.spec.templates` — шаблоны конструкции; внутри `template.tree` находится дерево модуля. Дочерние узлы в примере опущены.
- `params.spec.variants` — варианты типоразмеров. Размер может быть числом или выражением с переменной, как `v:_top_h`.
- `selected_variant` и `selected_template` — значения выбора варианта и шаблона в этой записи; не меняйте их без проверки связанных массивов.

При передаче `data` в запросе обновления объект заменяется целиком. Не отправляйте сокращённый пример вместо полученного `item.data`: так можно потерять настройки конструкции.

## Расширенное чтение (v2)

Для части разделов (фасады, материалы, техника, коммуникации, интерьер) есть расширенный метод чтения, который возвращает данные в более удобном виде (с ключами `items`, `count` и именами категорий):

```
GET  ОсновнойURL/api/get_items_v2/<раздел>?sync_key=ВАШ_КЛЮЧ
```

Используйте его, если стандартного `get_items` не хватает.


Пример с одной записью из каталога материалов:

```http
GET ОсновнойURL/api/get_items_v2/materials?sync_key=ВАШ_КЛЮЧ&per_page=1&start=0
```

## Важные замечания

- После любых изменений вызывайте **`GET api/apply_data?sync_key=...`** — иначе данные не попадут на сцену.
- Поля `id` категорий — это **ключи связи**. Сначала читайте структуру (`get_categories` / `get_items`), затем шлите обновления по существующим id.
- Точный перечень доступных методов и форматов для конкретного раздела всегда сверяйте с **разделом API в вашем кабинете** — он отражает актуальную версию.

## Коротко

Каталог управляется по шаблону `api/<действие>/<раздел>`. **Полный набор действий (get/add/update/remove) есть только у `materials`, `facades`, `handles`, `accessories`.** Разделы `tech`, `interior`, `comms` доступны через API только на чтение и добавление; `orders` — только чтение. Для модулей пользовательского каталога есть отдельные методы получения списка и записи, чтения одного модуля, добавления и изменения; удаление не поддерживается. GET — чтение (`sync_key` в строке), POST — запись (`data` + `sync_key`). После изменений вызывайте `api/apply_data`.
