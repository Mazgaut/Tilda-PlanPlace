Настройки конструктора — это «общие правила игры» для всей системы. Они влияют на то, как ведёт себя планировщик у всех пользователей: что попадает в PDF, можно ли менять размеры модулей, как вращаются объекты и как выглядит каталог. Менять эти параметры обычно нужно один раз при запуске, а потом — лишь изредка.

> **Важно.** После изменения настроек конструктора сделайте [жёсткую перезагрузку с очисткой кэша](/Tilda-PlanPlace/lichnyy-kabinet/) и не забудьте выгрузить настройки в планировщик. Иначе изменения не вступят в силу.

## Расчёт цен

**Выводить изображения модулей в спецификации.** Если включить, рядом с каждой позицией в PDF будет картинка модуля. Это нагляднее для клиента, но **увеличивает время генерации документа** — на больших проектах PDF будет собираться дольше.

## Защита PDF паролем

**Защитить генерацию PDF паролем.** Позволяет закрыть паролем доступ к скачиванию размеров и расшифровок, чтобы их могли открыть только менеджеры. Удобно, когда вы не хотите, чтобы клиент или конкурент получил полную деталировку с размерами. При включении появляется поле **«Пароль»** — задайте его здесь же.

## Функционал

**Позволить пользователям вводить свои размеры модуля.** Определяет, может ли клиент на сцене менять габариты модуля вручную. Для мебели на заказ это обычно включают. Для **модульных систем с фиксированными размерами** — выключают, чтобы клиент не задал размер, которого не существует в производстве. Точные пределы по ширине, высоте и глубине задаются ниже, в блоке [«Ограничения на размеры модуля»](#ограничения-на-размеры-модуля).

**Позволить пользователям менять тип фасада (Глухой / Витрина / Решётка).** Разрешает или запрещает пользователю переключать тип фасада у модуля. Если в вашем каталоге такие замены не предусмотрены, переключатель лучше выключить, чтобы не путать клиента.

**Разрешить пользователям менять фасады на отдельном модуле при раздельных фасадах (низ/верх).** Когда у модуля фасады разделены на верхнюю и нижнюю части, эта настройка позволяет клиенту менять фасад отдельно на каждом модуле.

**Вывести оси на сцену.** Отображение осей помогает точнее ориентировать объекты при расстановке.

**Вращение 360° и продвинутое управление пересечениями (beta).** Это **один общий переключатель** для двух связанных возможностей: свободного поворота модулей на произвольный угол и точного наложения объектов друг на друга (например, чтобы вставить технику в нишу или совместить декоративные элементы).

> **Как это работает.** При включении система запросит подтверждение. После включения глобально поворот 360° можно будет включать **индивидуально в настройках каждого модуля**. Если выключить этот переключатель, кнопка поворота исчезнет у всех модулей — даже у тех, где она была включена в индивидуальных настройках. Подробности — в статье [«Вращение и пересечения моделей»](/Tilda-PlanPlace/vraschenie-i-peresecheniya-modeley/).

**Включить функцию «Показывать пересечения объектов» по умолчанию.** Определяет, будет ли на сцене изначально включена подсветка конфликтующих (пересекающихся) объектов. Рекомендуется включить, чтобы сразу было видно, какие модули накладываются друг на друга.

**Объединение цоколей.** Объединяет цоколи соседних напольных модулей в единую линию вместо отдельных деталей под каждым модулем. По умолчанию включено.

**Отображать процесс сохранения.** Показывает индикатор прогресса при сохранении проекта — полезно на больших проектах, где сохранение занимает заметное время.

**Свои фотографии при генерации PDF.** Позволяет использовать собственные изображения проекта в PDF вместо автоматических ракурсов сцены.

**Отображать детальную настройку фасадов.** Включает индивидуальную настройку фасадов в меню модуля на вкладке «Ручки». По умолчанию включено.

**Скрыть блок уведомлений на сцене.** Убирает блок системных уведомлений из интерфейса сцены — полезно, если вы хотите более «чистый» вид планировщика для клиента.

## Смена материала

Модули могут иметь вложенную структуру — например, антресоль внутри верхнего модуля. Эти настройки определяют, что произойдёт при массовой смене материала. Для каждого случая доступны два режима:

- **Учитывать только группу верхнего модуля** — система смотрит на группу материалов модуля верхнего уровня. Если она подходит, материал меняется во всём модуле, включая вложенные; если не подходит — не меняется нигде.
- **Учитывать группы вложенных модулей** — система проверяет группу материалов у каждого модуля по отдельности (и верхнего, и вложенных). Материал меняется только у тех модулей, чья группа подходит.

Настройка задаётся раздельно:

- **Смена групп материалов деталей** — по умолчанию «только группа верхнего модуля».
- **Смена фасадов** — по умолчанию «группы вложенных модулей».

Это влияет, например, на то, перекрасится ли антресоль вместе с верхним шкафом или останется прежней.

## Отображение

**Использовать своё изображение для отражения.** Можно загрузить своё изображение (поле **«Файл отражения»**), которое будет отражаться в зеркальных поверхностях на сцене — например, в зеркалах шкафов. Это используется для брендирования: в отражении можно показать ваш логотип или фирменный интерьер.

**Включить на сцене для каталогов функцию «Отобразить всё».** Добавляет в каталоги возможность показать сразу все элементы — удобно при просмотре большого ассортимента.

**Выводить названия модулей в выпадающем списке с выбором ширины.** Помогает пользователю не запутаться при выборе размера, показывая название модуля рядом с шириной.

## Ограничения на размеры модуля

Блок появляется, когда заданы глобальные ограничения размеров. Здесь указываются минимальные и максимальные значения по **ширине**, **высоте** и **глубине**. Значение `0` означает «нет ограничения».

> **Обратите внимание.** Эти пределы действуют глобально. Точные ограничения удобнее задавать у каждого модуля отдельно на вкладке [«Размеры»](/Tilda-PlanPlace/osnovy-konfiguratora/).

## Коротко

Настройки конструктора задают глобальное поведение системы: внешний вид PDF и защиту паролем, свободу клиента в изменении размеров и типов фасадов, вращение 360° и пересечения, правила массовой смены материала, а также вид каталога и отражения. Настроили один раз — выгрузили в планировщик — проверили на сцене с жёсткой перезагрузкой. Дальше система работает по этим правилам для всех пользователей.
