Коллекция объединяет модули и допустимые для них варианты оформления в один готовый ассортимент. Дизайнер видит только совместимые элементы, фасады, ручки и материалы, поэтому ему проще собрать проект в рамках конкретной мебельной серии.

> **Статус функции.** Коллекции проходят проверку и могут быть недоступны в обычном меню личного кабинета. Материал опубликован для проверки порядка настройки; доступность функции уточните перед началом работы.

## Чем коллекция отличается от категории и группы материалов

- **Категория каталога** отвечает только за расположение модулей в папках.
- **Группа материалов** задаёт, какие плиты можно выбрать для определённой части изделия.
- **Коллекция** связывает набор модулей, допустимые материалы и комплектующие, значения по умолчанию, структуру каталога и, при необходимости, собственные цены.

Например, для коллекции кухонь можно оставить только нужные нижние и верхние модули, разрешить одну серию фасадов, несколько ручек и определённые декоры корпуса. Эти ограничения не требуют создавать копии всех исходных карточек.

## Из чего состоит карточка коллекции

### Наборы элементов

Набор определяет, какие модули входят в коллекцию. Элементы можно выбрать тремя способами:

- указать конкретные карточки;
- подключить целые категории каталога;
- разрешить типы элементов.

У набора можно задать название, видимость в каталоге, категории коллекции и один или несколько наборов правил. Порядок наборов меняется перетаскиванием.

Над списком показываются используемые и отсутствующие типы элементов. Отсутствующий тип означает, что он встречается внутри вложенного модуля, но не разрешён ни одним набором. Такой вложенный элемент может не построиться на сцене. Добавьте недостающий тип в существующий набор или создайте для него отдельный невидимый набор.

### Правила

Правила ограничивают доступный ассортимент внутри коллекции. Для каждого набора правил можно выбрать конкретные позиции, категории или ключи каталогов:

- фасады и цвета фасадов;
- цоколи;
- ручки;
- столешницы и плинтусы;
- фурнитуру;
- свободные 3D-модели;
- кромки;
- плитные материалы и декоры.

Один набор правил можно подключить к нескольким наборам элементов. Это удобно, когда нижние и верхние модули должны использовать одинаковые материалы и ручки.

> **Правила ограничивают, но не создают.** Если материал или группа не настроены в исходном модуле и глобальном каталоге, добавление ключа в коллекцию само по себе не создаст их в изделии.

### Доступные группы материалов

Для коллекции можно разрешить только нужные группы материалов и переопределить их состав или материал по умолчанию. Приоритет такой:

1. настройка конкретного модуля;
2. правило коллекции;
3. глобальная [группа материалов](/Tilda-PlanPlace/gruppy-plitnyh-materialov/).

Локальные и заблокированные группы сохраняют свою область действия. После настройки обязательно проверьте составной модуль: глобальная смена материала не должна перекрашивать защищённую локальную группу.

### Параметры по умолчанию

Коллекция может назначать значения, с которыми новый модуль появится на сцене:

- материал группы;
- фасад, его цвет и тип;
- группу материалов остеклённого фасада;
- цоколь;
- вариант плинтуса столешницы.

Значение по умолчанию должно входить в разрешённый ассортимент коллекции. Иначе дизайнер увидит пустой выбор или первый доступный вариант вместо ожидаемого.

### Категории коллекции

По умолчанию коллекция использует категории исходных каталогов. Если включить собственные категории, можно собрать более простое дерево специально для дизайнеров: например, «Нижние модули», «Верхние модули» и «Пеналы», независимо от внутренней структуры общей базы.

Создайте дерево категорий, затем привяжите нужные категории к наборам элементов. Пустая категория не добавляет в коллекцию модули сама по себе.

## Как настроить коллекцию

Настраивайте коллекцию в следующем порядке. Создание названия, набора или правила само по себе ещё не связывает их друг с другом.

| Этап | Что требуется заранее | Результат |
|---|---|---|
| Подготовить исходные карточки | Ассортимент серии и рабочие конструкции | Модули, материалы и комплектующие для коллекции |
| Создать коллекцию и наборы | Исходные модули и вложенные элементы | Полный состав серии |
| Создать и привязать правила | Наборы элементов и нужные материалы | Разрешённые варианты для каждого набора |
| Задать начальную комплектацию | Разрешения и существующие группы материалов | Значения по умолчанию |
| Настроить общие элементы | Правила для столешниц, плинтусов и цоколей | Поведение объединённых элементов |
| Настроить категории, меню и цены | Состав, комплектацию и артикулы | Удобный каталог и проверяемый расчёт |
| Добавить коллекцию в меню сцены | Сохранённые настройки | Возможность выбирать модули коллекции |

Собственные категории, ограничение меню и готовые цены необязательны. Состав коллекции и привязку правил нужно проверить в любом случае.

### Шаг 1. Подготовьте каталог

1. В [Каталоге элементов](/Tilda-PlanPlace/katalog-elementov/) подготовьте модули серии. Проверьте их построение без коллекции.
2. Проверьте вложенные элементы: ящики, полки, секции и другие автоматически добавляемые части. Запишите используемые типы элементов.
3. Подготовьте карточки фасадов, декоров, ручек, плит, кромок и фурнитуры. Если серия использует столешницы и цоколи, подготовьте и их.
4. Настройте группы материалов в исходных конструкциях. Например, группа «Корпус» должна уже использоваться у соответствующих деталей.
5. Если нужны переменные серии, создайте и сохраните их в разделе [«Глобальные переменные»](/Tilda-PlanPlace/globalnye-peremennye/).

**Проверка:** исходный модуль собирается полностью и имеет ожидаемый состав в спецификации. Правила коллекции не исправляют ошибки исходной конструкции.

### Шаг 2. Создайте коллекцию

В личном кабинете откройте **«Коллекции» → «Добавить коллекцию»**. Укажите название и при необходимости порядок, затем нажмите **«Сохранить и выйти»**. Ключ формируется при создании; в форме редактирования он доступен только для чтения.

Откройте настройки созданной коллекции. Дальнейшие действия выполняются на вкладках её карточки.

### Шаг 3. Создайте наборы элементов

На вкладке **«Наборы элементов»** создайте набор. Через **«Добавить элементы»** выберите **«Конкретные элементы»**, **«Категории каталога»** или **«Типы элементов»**.

Разделяйте наборы по различиям в правилах и показе каталога. Например, «Нижние шкафы» и «Верхние шкафы» удобно держать отдельно, если они должны находиться в разных категориях.

| Состояние набора | Как работает |
|---|---|
| Активен и виден | Элементы участвуют в коллекции и доступны для самостоятельного добавления из каталога |
| Активен, но не виден | Элементы участвуют в коллекции, но не показываются как самостоятельные позиции |
| Выключен | Набор не участвует в формировании коллекции |

Проверьте сводку недостающих типов над наборами. Кнопка добавления недостающих типов создаёт активный скрытый набор для внутренних элементов. **У созданного таким способом набора ещё нет правил:** назначьте их на следующем шаге.

Если разрешение целого типа слишком широкое, включите конкретные необходимые карточки. Затем проверьте каждый вариант наполнения: сводка типов помогает найти пропуски, но не заменяет проверку полного модуля.

### Шаг 4. Создайте правила и назначьте их наборам

1. На вкладке **«Правила»** создайте набор правил, например «Материалы серии Модена».
2. Добавьте **«Доступные материалы»** и разрешите нужные карточки или категории. Учитывайте не только видимые варианты оформления, но и кромки, фурнитуру, модели и декоры, из которых строится модуль. Разрешение фасада не заменяет разрешения нужных ему декоров.
3. Через **«Доступные группы материалов»** настройте разрешённые материалы и толщины существующих групп.
4. Если какой-то раздел не нужно ограничивать, добавьте для него **«Доступно всё»**.
5. Вернитесь в **«Наборы элементов»** и добавьте созданный набор правил в блок **«Правила»** каждого нужного набора, включая скрытые наборы внутренних элементов.
6. Проверьте, что набор элементов, набор правил и сами правила включены.

**Главная зависимость:** правило действует на элементы через привязку к набору. Само создание правила не назначает его всем модулям.

Коллекция закрыта по умолчанию: раздел, не разрешённый ни одним применимым правилом, будет пустым. При этом разрешения нескольких правил **складываются**. Если одно разрешает белые фасады, а другое — серые, доступны оба варианта. Более узкое правило не отменяет разрешение, выданное другим.

**«Доступно всё»** открывает выбранный раздел целиком. Если один модуль входит в несколько наборов, проверьте правила всех этих наборов: через другой набор он может получить дополнительные варианты.

### Шаг 5. Задайте начальную комплектацию и переменные

На вкладке **«Параметры»** в блоке **«Параметры по умолчанию»** назначьте начальные фасад и цвет, ручку, цоколь, столешницу, плинтус и другие необходимые варианты. Для цоколя выберите также строку размера: от неё зависит высота.

**Сначала разрешите вариант, затем назначайте его по умолчанию.** Начальное значение не заменяет разрешение в правилах. Пустое поле не задаёт нового значения от коллекции — остаются применимые настройки модуля или каталога.

Для группы материалов проверьте приоритет: **настройка конкретного модуля → настройка коллекции → общая настройка каталога**. Если материал отличается от ожидаемого, сначала проверьте переопределение в карточке модуля.

На вкладке **«Переменные»** включите **«Переопределить»** напротив нужной переменной и задайте стартовое значение. Переменная должна заранее существовать в сохранённом списке глобальных переменных каталога. Это значение по умолчанию: дизайнер может изменить его и сохранить свой выбор в проекте.

Встроенные значения, вычисляемые по комплектации, например высота цоколя и толщина фасада, на этой вкладке не задаются. Сначала настройте соответствующие карточки в параметрах по умолчанию.

**Проверка:** добавьте новый модуль коллекции и сравните фактические фасад, цвет, ручку, материал корпуса и высоту цоколя с назначенными значениями.

### Шаг 6. Настройте объединяемые элементы

В блоке **«Объединяемые элементы»** определите, откуда общие столешницы, плинтусы и цоколи получают правила:

- **«Наследовать правила из элементов»** — объединённый элемент получает совокупность правил участвующих элементов;
- **«Задать правила»** — действуют выбранные здесь наборы правил; правила исходных элементов для общего элемента не учитываются.

Во втором режиме сначала создайте наборы правил на шаге 4, затем назначьте их здесь. Они должны разрешать необходимые общие элементы и их материалы.

Принадлежность одной коллекции и одному каталогу — необходимое условие объединения. Оно не отменяет требований к материалу и геометрии. Соседние модули разных коллекций не получают одну общую столешницу или объединённый плитный цоколь.

### Шаг 7. Настройте категории и меню модуля

Если достаточно структуры общего каталога, собственные категории можно не создавать. Для отдельной структуры:

1. На вкладке **«Параметры»** включите **«Настроить категории»**.
2. На вкладке **«Категории»** создайте нужные разделы.
3. Вернитесь в **«Наборы элементов»** и назначьте каждому видимому набору категории.

Категория назначается всему набору. Если элементы должны лежать в разных разделах, разделите набор. Созданная категория сама не заполняется; скрытый набор не становится видимым после назначения категории.

Когда собственные категории включены и назначены, коллекция открывается единым каталогом с этими категориями, без отдельного шага выбора типа элементов.

На вкладке **«Меню модуля»** при необходимости включите **«Ограничить»** и оставьте нужные вкладки, блоки, группы материалов, переменные и типы вложенных элементов. Это настройка видимости панели: она не заменяет разрешения материалов и не включает внутренние элементы в состав коллекции.

Для отдельных наборов используйте правило **«Меню модуля»**. Разрешения из карточки коллекции и правил складываются: снятие отметки в одном месте не скроет вкладку, разрешённую другим применимым правилом. При выключенном ограничении раздел показывается полностью.

### Шаг 8. Настройте расчёт и спецификацию

Обычный расчёт по материалам и комплектующим не требует прайс-листа готовых модулей. Если нужны готовые цены, сначала завершите настройку комплектации и проверьте артикулы исходных карточек. Затем на вкладке **«Цены»** задайте формулы составного артикула и таблицу соответствующих цен.

Например, формула `MODENA-{variant}-{facade_mat}` использует артикул варианта размера и артикул материала фасада. Для условных артикулов `N600` и `WHITE` нужна строка `MODENA-N600-WHITE`. Это пример схемы; используйте фактические артикулы ваших карточек.

Формулы проверяются сверху вниз до первого совпадения. Если найдена готовая цена, модуль выводится как готовая позиция вместо подробного состава. Если совпадения нет, подмена готовой ценой не происходит — это не означает нулевую цену.

Проверьте **«Объединять позиции коллекций»** в основных настройках расчёта цен. При раздельном расчёте одинаковые товары разных коллекций попадают в разные строки, а отдельное округление количества может увеличить итог.

На вкладке **«Цены» → «Вывод блоков спецификации»** переключатель **«Переопределить отображение»** позволяет выбрать видимые блоки для коллекции. Скрытие блока не исключает его стоимость из итога. При выключенном переопределении действует общая настройка.

### Шаг 9. Добавьте коллекцию в меню сцены

Сохраните коллекцию. В [меню планировщика](/Tilda-PlanPlace/nastroyka-menyu-planirovschika/) добавьте пункт **«Коллекции»** и выберите коллекции, которые он должен показывать. При необходимости ограничьте категории каждой коллекции.

Если дизайнер должен менять материалы сразу у модулей одной коллекции, настройте соответствующие панели выбора с привязкой к ней. Обычная общая панель без такой привязки не является переключателем всех коллекций сразу.

Выгрузите сохранённые настройки в конструктор и откройте сцену с обновлёнными данными. Для проверки добавляйте модуль именно из пункта выбора коллекции. Размещение той же карточки из обычного каталога не проверяет правила коллекции.

### Шаг 10. Проверьте серию на небольшом проекте

Для первого теста возьмите условную серию «Модена»: один нижний шкаф, один верхний, скрытый набор внутренних элементов, два цвета фасада и одну ручку. Проверьте весь сценарий ниже и только затем расширяйте ассортимент.

## Если результат отличается от ожидаемого

| Что видно | Что проверить |
|---|---|
| Модуль не появился в коллекции | Состав набора, его активность и видимость, фильтр категорий в меню сцены |
| Шкаф построился без внутренней части | Принадлежность карточки активному набору и правила скрытого набора |
| Материалы или ручки недоступны | Разрешение раздела и привязку активного набора правил к элементам |
| Доступен лишний вариант | Другие наборы модуля и «Доступно всё»: разрешения складываются |
| Начальный материал отличается | Настройки модуля, правило группы и доступность варианта по умолчанию |
| Вкладка «Переменные» пуста | Сохранённый список глобальных переменных; встроенные расчётные значения здесь не показываются |
| Категория создана, но не видна | Назначение категории видимому набору и наличие в нём доступных элементов |
| Вкладка меню осталась видимой | Разрешения из других применимых правил |
| Нет ожидаемой готовой цены | Артикулы исходных карточек, результат формулы, наличие строки и порядок формул |
| После разделения по коллекциям вырос итог | Отдельное округление количества и настройку объединения позиций |

## Что проверить на сцене

- В каталоге присутствуют все корневые и вложенные модули.
- Для каждого модуля доступны только разрешённые фасады, ручки и материалы.
- Значения по умолчанию применяются при первом добавлении.
- Локальные группы материалов не меняются глобальным выбором.
- Столешницы, плинтусы и цоколи корректно создаются для соседних модулей.
- После сохранения и повторного открытия проект сохраняет выбранную коллекцию и её правила.

Проект хранит снимок настроек коллекции, чтобы ранее собранная мебель продолжала открываться после изменения каталога. При этом актуальные данные существующей коллекции имеют приоритет. Поэтому после существенного изменения ассортимента проверяйте как новый, так и ранее сохранённый проект.

## Цены коллекции

Для серийной мебели коллекция может заменить подробный расчёт модуля готовой позицией с фиксированной ценой. Порядок настройки описан выше, в шаге 8. Если один составной артикул встречается в таблице несколько раз, применяется первая строка сверху. Перед использованием готовых цен проверьте все продаваемые комбинации комплектации.

## Коротко

Коллекция — это готовый ассортимент внутри общей базы PlanPlace 2. Она объединяет модули, ограничения по материалам и комплектующим, значения по умолчанию и собственное дерево категорий. Начинайте с наборов элементов, затем добавляйте правила и обязательно проверяйте вложенные типы и локальные группы на сцене.
